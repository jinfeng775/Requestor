# Realtime PRD

## 背景
Requestor 当前以 HTTP 请求/响应为主。参考 Hoppscotch 的 Realtime 区域，本次新增一个独立的 `Realtime` 工作区，提供 4 类实时协议调试能力：WebSocket、SSE、Socket.IO、MQTT。

## 产品目标
- 在不破坏现有 HTTP 工作流的前提下新增实时协议调试能力。
- 以标签页方式管理多个实时连接会话。
- 允许用户保存实时配置、查看连接历史、复用环境变量。
- 保持离线优先和本地持久化模式。

## 非目标
- 本期不做自动恢复实时连接。
- 本期不做复杂断线重连策略。
- 本期不做二进制消息深度可视化。
- 本期不把 HTTP 与实时协议抽象成统一“万能请求模型”。

## MVP 范围
### 工作区
- 新增 `Realtime` 工作区入口。
- 工作区内提供协议 tab：`WebSocket`、`SSE`、`Socket.IO`、`MQTT`。
- 每个实时会话支持独立标签页。

### 协议能力
- WebSocket：连接、断开、发送文本、接收消息。
- SSE：连接、断开、接收事件流。
- Socket.IO：连接、断开、监听事件、发送 emit。
- MQTT：连接、断开、订阅、取消订阅、发布消息。

### 通用能力
- 配置编辑：URL/endpoint、headers、query、认证、协议专属字段。
- 消息面板：入站/出站/系统事件日志。
- 清空日志。
- 连接状态展示：connecting / connected / disconnected / error。
- 保存到集合。
- 单独的 realtime history。
- 环境变量解析复用现有能力。

## 用户流
1. 用户切换到 Realtime 工作区。
2. 新建一个实时标签页并选择协议。
3. 填写连接配置并连接。
4. 观察入站消息；在支持发送的协议中发送消息或发布事件。
5. 将配置保存到集合，稍后再次打开。
6. 在历史中查看最近连接记录。

## 成功标准
- 新功能不影响现有 HTTP 请求发送、历史、集合与环境变量能力。
- 四种协议都具备可用的基础 MVP。
- 所有实时连接由 Electron main 持有并在关闭时正确清理。
- 历史与持久化有独立数据结构，不污染现有 HTTP 数据。
